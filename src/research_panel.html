About scale and depth

When selecting µm, enter micrometres per source pixel. For an old calibration expressed as px/µm, use its reciprocal: 2 px/µm equals 0.5 µm/px. ROIs and images must share the same pixel origin, size and orientation. The scale assumes isotropic pixels with equal X and Y. Section order sets display spacing only; it cannot establish anatomical depth or volume.

Supported files and missing sections

Link a TIFF, PNG or JPG image and an ImageJ .roi file or ROI ZIP to each section. A measurement CSV is optional. Register different sections as separate rows, and do not treat montage tiles of a single section as multiple sections.

Retain a genuinely missing section as excluded, with its reason. Use Delete row for an unused empty row. Measured depth requires an XY scale and the actual z coordinate of every section, including excluded sections. Origin, orientation and alignment must also be verified manually.

This view stacks the entered observed planes. It performs no automatic segmentation or anatomical registration, and missing ROIs or measurements are not filled with 0 or estimates. Unsupported data are reported as errors. Project limits are 256 MiB per file, 512 MiB of source data per binary project, 100 sections and 4,998 original files. Single-page uncompressed 8-bit gray or RGB strip TIFFs support up to 80 million pixels. Other supported TIFFs are limited to 128 MiB per file, 40 million pixels and 128 MiB of decoded channels. PNG and JPEG images remain limited to 40 million pixels. Use UTF-8 CSV.

How to continue research with colleagues
  1. Use ‘Save project’ after applying the inputs. The ZIP includes the original observation files and a manifest; legacy JSON projects remain readable. Send the downloaded file to a colleague.
  2. The colleague inspects the data with ‘Open project’ and adds review records.
  3. Import the colleague’s saved review file with ‘Merge review files’. Records whose project ID and data fingerprint match are merged.

Save inputs downloads an editable input draft, including pending file and calibration changes. It does not include the last assembled 3D project, image-analysis work or study-pipeline work. Exchange is currently file-based. Accounts, server storage and real-time co-editing are not provided. Reviewer names are display names entered by the author. Keep source images and ROIs separately, and share a new project file after changing the data.
