# Image to reviewed measurements

This tool reviews manual, ImageJ or model-proposed ROIs against the original image. A model is not required to import ROIs or draw observations. No validated Nissl model is included, and synthetic software tests do not establish anatomical accuracy.

1. Open **My research → Image analysis**. Choose the original, single-page TIFF for one physical section. Confirm that the image contains one section; a stitched tile montage is acceptable, a sheet of multiple sections needs separation first. The current browser limit is 128 MiB and 40 million pixels (128 MiB of decoded pixels). Keep the unmodified original separately.
2. Import existing ImageJ ROI ZIP or `.roi` files, or select **Start manual review**, choose a tissue or observation label, and draw on the TIFF. Imported area regions, open lines and points keep their distinct geometry. Review the suggested tissue or observation label, any optional region/lobule name, and the alignment with the source TIFF. Unknown labels stay unassigned until reviewed. A trained model is optional under **Advanced**. ONNX inference uses the downloadable local runner and its matching manifest; Local Lab pixel-forest JSON runs locally in the browser. Both require externally supplied trained weights.
3. Inspect every ROI. **Draw new ROI** uses the selected label: CB, ML, GL, WM, OTHER and Unassigned create area polygons; PL and Fissure create open lines; Landmark creates points. An area needs at least three vertices, an open line at least two, and a point ROI at least one point. Existing ROIs can be edited or redrawn while retaining their geometry kind. Components and holes apply only to area ROIs. You can correct labels, edit or remove existing coordinates, exclude with a reason, and undo/redo edits. Vertex insertion adds a midpoint on an area edge or an open-line segment; it is unavailable for point ROIs and the final endpoint of an open line. Add points by redrawing the point ROI. A label such as PL, fissure or landmark does not establish anatomical identity. A mismatch between a tissue/observation label and its geometry blocks approval; acknowledging a QC warning does not override that requirement. Correct the label or geometry, use OTHER for a deliberately reviewed generic annotation, or exclude the ROI with a reason. Original input geometry and source files remain unchanged evidence. Geometry screening flags area overlap, layer boundaries outside CB and missing labels; inspect flags and record a QC decision before approval. Screening does not establish anatomy or fill missing tissue.
4. Record animal/section identifiers, the boundary protocol and known pixel sizes (µm/px, independently for X and Y). Leave unknown calibration, Z, thickness and sampling interval blank. Section thickness is not the interval between sampled sections. No whole-organ volume is inferred here.
5. Check the boundaries and measurement definition, enter your reviewer name and protocol, and approve. Approval records your decision on this version; it is not proof of anatomical correctness. Any subsequent coordinate, calibration or exclusion change requires approval again.
6. Use **Save review draft** to pause work; reopen the matching TIFF and draft to resume. Reopened drafts require fresh approval. Download the result ZIP before leaving. It retains the source TIFF, original ROI/prediction input, review/provenance and measurement table alongside the included ImageJ ROI files. Imported ImageJ bytes and optional source CSV are preserved byte-for-byte. A browser-generated result also includes the model bytes used to generate it; imported predictions report when those bytes are unavailable. Keep the full archive, including excluded-region reasons. Work stays local to this browser and is not saved to a server. Image analysis also creates browser recovery copies as described below.

The preview displays 8-bit colour even for 16-bit TIFFs; low-range 16-bit images may appear dark. There are no contrast-window controls yet. The original pixel values used by the local runner and retained in the archive are unchanged.

The attached ROI file list identifies each original input. **Remove file** removes that source's associated ROIs from the active review while retaining the previous recovery copy and other attachments. **Clear all reviewed ROIs** clears the current ROI review. These actions do not delete files on your computer. Check the displayed geometry and review again after changing the active inputs.

**Clear prediction selection** and **Clear draft selection** clear those selected input files while retaining the existing review and its recorded source evidence. They do not silently erase the accepted review. **Original model file for this result** is a separate evidence attachment from the model selected for generating new drafts. Its SHA-256 must match the result's declared model hash. Attaching or clearing it does not change the active generation model; a matching hash verifies file identity, not model accuracy.

Measurements depend on geometry kind. Area ROIs have area and closed-boundary perimeter. Open lines have path length and no area; their last vertex is not joined to the first. Point ROIs have point count and no area or path length. A point count is the number of recorded annotations, not an automatically validated cell count. A PL-labelled open path does not establish Purkinje cell count or layer thickness. Metrics that do not apply remain missing rather than zero.

A name such as `GL+WM` must not be silently classified as GL or WM. Ambiguous imported labels remain **Unassigned** until reviewed. If the ROI intentionally represents a generic or combined area, select **OTHER · Other or combined region**, record its optional region/lobule name and apply the label before approval. Its own area and perimeter remain measurable; it is not automatically a single tissue compartment and must not enter a GL-only or WM-only volume as though it were one.

The CSV does not sum CB and its constituent layers, estimate thickness from area/perimeter or manufacture missing values. Anisotropic pixel sizes are supported for physical measurements: X and Y displacement are scaled independently. No physical values are available without both X and Y scales. Polygon area uses the continuous even-odd interior rule, including holes; unchanged source ellipses retain analytic area. Closed-boundary perimeter follows the recorded segments, including hole boundaries, and is not ImageJ's corner-corrected perimeter. Line width and display colour never create scientific area. The original proposal remains in the audit record.

The export retains the existing identity, calibration and provenance columns and adds `kind`, `source_type`, `original_name`, `source_file`, `region`, `length_px`, `length_um`, `point_count`, `point_coordinates_px` and `point_coordinates_um`. Point-coordinate cells contain JSON arrays. Physical point coordinates use the source image's top-left origin with the recorded X/Y scales; they are not automatically atlas or anatomical coordinates. Excluded or inapplicable measurements remain blank.

**Compare an existing measurement CSV** optionally retains up to 2 MiB of source CSV as context. Exact ROI IDs or unambiguous original/exported ROI names can be linked. Conflicting identities, duplicate rows or duplicate metric columns are not reconciled automatically. Recognized metric columns include `area_px2`, `area_um2`, `perimeter_px`, `perimeter_um`, `length_px`, `length_um` and `point_count`, including explicit unit spellings such as `Area (µm²)` and `Length (µm)`. A plain `Area` or `Length` column has no inferred unit. Source cells, empty values and missing cells remain as imported; formulas stay literal text. Comparison never replaces geometry or calibration, and agreement does not validate a shared boundary definition. Clearing or replacing CSV context invalidates approval while preserving geometry.

To continue in **Study & 3D**, select **Use image review**, confirm the Study protocol and review the transferred section. Image-workspace approval is retained as provenance; Study requires a fresh approval for its current evidence. Physical volume requires suitable area ROIs from at least two sections with measured Z and verified X/Y calibration. Line and point annotations do not become tissue areas or contribute a fabricated volume.

For the separate **Observations** workspace, extract the original image and the dedicated `rois.zip` from each approved archive, then register them per section. Use measured depth only when actual Z, image scale, orientation and order are known. This observed-plane viewer assumes equal X and Y pixel scales; anisotropic data need an explicit, documented coordinate conversion before it is used. Do not silently substitute the mean pixel size.

The current site is a research prototype. It has no validated production Nissl model or server-side inference queue. Physical reconstruction and animal-level comparison are software workflows with input requirements and assumptions; they do not establish independent-animal biological validity. Atlas alignment requires explicit reference and landmark evidence rather than automatic anatomical identification.

## Direct browser generation

With a compatible, user-trained Local Lab pixel-forest JSON model, choose the model in the image workspace. The site computes a native-pixel ROI draft in a cancellable Worker; an image selected later can generate automatically. This is real model inference and requires trained weights, which are not included. ONNX models continue to use the local runner. The same original-source matching, calibration, editing and approval rules apply. Failed or cancelled jobs retain the preceding review. See BROWSER_MODEL.md for the numerical contract and verification limits.

When native inference succeeds but ROI conversion exceeds topology/complexity limits, download the retained native label map with its exact source/model evidence. You can preview those labels over the TIFF and start a manual review. Labels remain unreviewed; automatic cleaning, discarded islands or an empty approved result are never substituted. Keep the label-map archive or full workspace backup because a lightweight review draft records its reference hashes without embedding the large native map/model.

## Browser recovery and replacing a result

Image analysis automatically stores the unchanged TIFF, preview, original prediction, review history, active compatible model and pending form fields in IndexedDB. Wait for **Recovery copy saved on this browser**. After a reload, open **Browser recovery**, choose a copy and select **Restore selected copy**. Source hash/dimensions and prediction bytes are checked again. Pending fields remain pending; previous approvals remain in history and a fresh review is required. Restoring starts a new working copy so the older copy remains available.

A different TIFF, replacement prediction, reopened draft or regenerated ROI result is prepared before replacing an existing review. Select **Keep current review** to discard that candidate, or **Accept new result** to save the current work first and switch. Saving failure blocks the switch. Earlier sessions remain in Browser recovery. This is version retention, not an anatomical side-by-side comparison or automatic validation of the new result.

Recovery is specific to this browser profile and site address. Browser cleanup, private mode and storage eviction can remove it. Up to 20 sessions are kept, subject to browser capacity; nothing is silently evicted by this application. Delete an unneeded copy explicitly to make space, then retry saving. Changes made in another tab are protected by revision checks. During an unsaved write, failure, processing or an unaccepted candidate, normal page departure requests a browser warning; browsers may suppress warnings or terminate without one. Only completed recovery transactions are durable. The most recent unsaved keystrokes or an in-progress drag can still be lost on a crash.

Keep originals and a downloaded backup. Downloads are reported as requested, because the page cannot verify that the browser wrote the file to disk. If local storage fails, keep the tab open, apply or explicitly discard pending fields, and download a review draft or approved archive. Image analysis also participates in the full workspace backup, including original files, CSV/ROI/model evidence and native label maps when present. Backup import verifies original hashes before replacement and requires fresh approval. The Browser recovery list described here remains specific to Image analysis.
